# Streamflix Desktop 1.4.3 — HiDPI artwork clarity

## Fixed

- **HiDPI catalog artwork:** cards, editorial hero and detail backgrounds now resize from the decoded source to the **physical** screen pixel dimensions. Previous code cached only a 1x image at the Swing component's logical size; on 125%, 150% and 200% Windows monitors that bitmap was subsequently enlarged by the desktop display transform, causing unnecessary blur.
- **Scale changes:** artwork is regenerated from the untouched decoded source when a window changes logical dimensions or device scale. Identical layouts reuse the cached bitmap during scrolling; changing monitors does not reuse an outdated 1x copy.
- **Missing artwork:** a panel without an image URL no longer schedules a redundant asynchronous null callback. Honest fallback graphics remain unchanged.

## Evidence and limits

- `ArtworkPanelTest` renders synthetic high-frequency source imagery at 100%, 125%, 150% and 200%, checks exact physical cache dimensions, reuse at the same scale, regeneration on scale changes and invalidation when the source changes. This test is also executed by the Windows CI build.
- The current TMDb metadata path requests `w1280` backdrops and `w780` posters; the URL-specific decoded image cache is preserved. Previous repairs already removed a separate `w1280` to `w780` downgrade on landscape cards.
- **Data Saver** applies to streamed video and does not control artwork image dimensions.
- HiDPI-aware rendering preserves available detail but cannot recreate detail missing in the original provider asset. Android and Desktop may also select different images; exact Android-source parity has not been independently verified.
